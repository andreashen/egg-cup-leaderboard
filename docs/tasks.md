# 英超竞猜榜单项目实施任务清单

## 当前里程碑

- [ ] 第一里程碑只打通官网积分榜数据链路：抓取、规范化、原始快照落盘和规范化结果落盘。
- [ ] 第一里程碑默认优先使用 `premierleague.com` 页面背后的 JSON 数据入口。
- [ ] 第一里程碑若遇到 JSON 入口不可用或字段漂移，直接失败并保留日志，不在本轮补做 HTML 降级抓取。
- [ ] 第一里程碑不依赖赛程明细接口，以 `standings + metadata` 作为最小闭环。
- [ ] 计分引擎、静态页面和自动发布保留在后续阶段实现，不纳入当前开发完成标准。

## 1. 项目初始化

- [ ] 建立第一版目录结构，包括 `src/`、`data/`、`config/`、`artifacts/`、`site/` 和 `.github/workflows/`。
- [ ] 初始化 Python 3.9+ 项目，并使用 `pyproject.toml` 管理依赖与命令入口。
- [ ] 补充 README 中的项目说明、运行入口和发布方式。

## 2. 静态输入整理

- [ ] 定义玩家竞猜 CSV 的正式格式，并校验示例文件。
- [ ] 建立 `data/seasons/2025-26.yml`，写入赛季编号、参赛球队、升班马和基础元数据。
- [ ] 建立 `data/team_aliases.csv`，覆盖中文名、英文名、简称和官网命名。
- [ ] 抽取 `data/baselines/2024-25_table.csv`，形成可供计分使用的标准数据文件，并根据规则将升班马映射到第 18、19、20 名的基准位置。

## 3. 数据模型与规范化

- [ ] 定义赛季配置、球队基线、玩家竞猜、官方赛果快照、计分结果等核心模型。
- [ ] 实现竞猜 CSV 读取与标准化逻辑。
- [ ] 实现球队名称标准化与唯一映射校验逻辑。
- [ ] 设计中间产物的 JSON 结构，供计分和页面生成共用。

## 4. 官网数据源适配

- [ ] 调研并确定 `premierleague.com` 第一版可用的 JSON 数据抓取路径，并记录请求入口与字段映射。
- [ ] 实现官网数据抓取模块，获取积分榜和轮次信息。
- [ ] 实现官网积分榜响应解析与规范化输出。
- [ ] 为抓取结果落盘原始快照和规范化结果，便于排查。
- [ ] 设计失败处理、超时、重试和日志输出机制。

## 5. 计分引擎实现

- [ ] 实现前四计分逻辑：计算公式为 `Ti × (1 - abs(Pi - Gi) / 20)`，支持负分结果。
- [ ] 实现黑马计分逻辑：判断排名提升情况（>=3名），覆盖成功加分与失败扣分规则。
- [ ] 实现黑驴计分逻辑：判断排名下降情况（>=3名），覆盖成功加分与失败扣分规则。
- [ ] 实现无效竞猜校验与拦截：识别并处理违反规则的竞猜（如上赛季前三猜黑马、升班马猜黑驴），并记录异常状态。
- [ ] 整合计分结果，输出玩家总分、排名和详细的分项解释（包含公式中的具体代入值）。

## 6. 结果验证

- [ ] 用规则文档中的示例构造自动化样例，验证计分结果。
- [ ] 用真实竞猜 CSV 做一次端到端试算，检查总榜和分项是否符合预期。
- [ ] 对球队映射和规则边界条件补充针对性测试。

## 7. 静态页面生成

- [ ] 设计 GitHub Pages 首页结构，展示标题、更新时间、轮次信息和总积分榜。
- [ ] 实现首页内展开和收起的玩家明细展示，包括前四、黑马、黑驴的分项说明。
- [ ] 实现当前英超积分榜快照展示。
- [ ] 让页面从计分结果 JSON 渲染，而不是把逻辑写死在页面里。

## 8. 自动更新与发布

- [ ] 编写本地更新入口，支持一键执行抓取、计分和页面生成。
- [ ] 配置 GitHub Actions 每 6 小时定时任务和手动触发任务。
- [ ] 配置 GitHub Pages 发布流程。
- [ ] 确保抓取失败时不发布半成品页面。
- [ ] 如内容无变化，避免无意义发布或提交。

## 9. 收尾与文档

- [ ] 完善 README 的使用说明、数据源说明和维护方式。
- [ ] 记录常见故障排查路径，如抓取失效、名称映射失败、计分异常。
- [ ] 补充下赛季复用说明，明确需要更新哪些配置、映射和基线数据。
